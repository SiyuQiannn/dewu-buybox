# 得物 Buybox 购买选项决策体验优化 PRD

## 1. 项目概述

### 1.1 项目来源

在 TikTok Shop 战略分析实习期间，我曾参与不同电商平台 Buybox 机制的案头拆解。通过对亚马逊、国内综合电商百亿补贴频道、得物等平台的观察，我发现 Buybox 并不只是一个价格排序模块，而是平台组织供给、分配流量、建立用户交易信任和提升下单效率的核心产品机制。

得物的多购买选项机制具有典型的 Buybox 特征：平台将同一商品下不同价格、渠道、成色和履约时效的购买方案聚合展示，由用户在下单前完成选择。与亚马逊“单一 Winner”不同，得物采用的是更符合国内用户比价习惯的“多购买选项平铺”形态。

本项目是基于实习期间 Buybox 研究兴趣延展出的独立产品项目，目标不是重构得物交易机制，而是围绕用户在购买选项页的理解、比较和选择过程，优化得物 Buybox 的前台信息表达与决策辅助体验。

### 1.2 项目一句话

围绕得物“尺码 + 购买选项页”，设计「选项怎么选」能力，在不暴露具体供应商身份、不破坏平台统一正品心智的前提下，帮助用户理解不同购买选项的渠道、成色、时效、查验和售后差异，从而降低正品焦虑与售后预期偏差，提升下单决策效率。

### 1.3 项目定位

本项目主线定位为电商交易产品项目，「帮我选」作为决策辅助模块存在。

项目重点不是“新增一个复杂导购功能”，而是解决得物多购买选项场景下的信息表达断层：

- 用户看到多个购买选项，但不知道差异来自哪里；
- 用户看到不同物流时效，但担心快到选项是否跳过查验；
- 用户看到不同渠道和成色标签，但容易将渠道差异误读为正品差异；
- 用户看到平台统一保障文案，但不同选项实际售后规则可能存在差异；
- 用户缺少官方横向对比工具，只能手动记忆、截图或去社媒搜索。

因此，本项目的核心是“购买决策体验优化”。「帮我选」只根据当前选项和用户关注点给出建议，不替代官方规则说明。

## 2. 业务背景与产品现状

### 2.1 得物多购买选项机制

得物作为潮流电商平台，长期以“多报价 + 先鉴别后发货”为核心交易特色。用户在同一商品详情页下，通常会看到多个购买选项。这些选项可能在价格、物流时效、渠道标签、商品成色和售后规则上存在差异。

该机制对平台、商家和用户均有价值：

- 对平台：聚合多渠道供给，提升商品可买性和价格竞争力，同时通过查验体系统一建立正品心智。
- 对商家：围绕价格、履约效率和服务能力参与同款商品竞争。
- 对用户：在同一商品下比较多个购买方案，按价格、时效、渠道和成色偏好选择。

但多购买选项机制也带来一个前提要求：用户必须能够理解不同选项之间的真实差异。如果信息表达不足，用户容易把本应属于渠道、成色、时效或售后规则的差异，误读为正品可信度差异。

### 2.2 消费者前台可见信息

从消费者视角看，得物当前购买选项页主要展示以下信息：

1. 渠道标签
   - 品牌官方
   - 品牌专供
   - 全球购
   - 保税直发
   - 普通渠道通常不展示显性标签

2. 商品成色标签
   - 全新商品通常不额外标注成色
   - 95 分二手商品会展示 95 分 logo，并跟随“全新未使用”“轻微使用”“仅鞋盒瑕疵”等成色描述

3. 物流时效
   - 如 1-3 天到、2-5 天到、5-7 天到、十余日到等
   - 不同物流时效背后可能对应不同履约链路，但前台通常不展示具体发货模式名称

4. 价格与购买选项颜色
   - 蓝色选项为当前主要购买入口
   - 黑色选项通常为其他全新购买方案
   - 灰色选项通常与 95 分二手等非全新方案相关

### 2.3 前台未显性展示的信息

通过案头调研可发现，不同渠道标签和物流时效背后存在更细的履约链路。例如品牌官方、品牌专供可能存在不同备货和发出方式，普通无标签渠道也可能存在快慢不同的履约模式，全球购和保税直发分别对应跨境或保税链路。

但这些后台履约模式并不是消费者前台可见标签。用户真正看到的是：

- 这个选项有没有渠道标签；
- 这个选项是不是 95 分二手；
- 这个选项多少钱；
- 这个选项预计几天到。

因此，产品方案不应直接把“品牌入仓、品牌现货、品牌直发、闪电直发、普通发货”等后台履约词拿到前台做一级展示。更合理的做法是：不暴露后台履约模式名称，而是围绕用户关心的问题解释清楚：

- 为什么不同选项到货时间不同；
- 为什么 1-3 天到也经过查验；
- 哪些信息是渠道或成色差异；
- 哪些信息是售后权益和规则差异。

### 2.4 平台策略与用户需求之间的张力

得物通过平台统一对客和正品查验体系，对复杂供给结构进行了前台封装。这一策略本身具有合理性：平台不需要在消费者侧暴露具体供应商身份，而应通过统一查验和品质保障建立“在得物购买即享正品保障”的平台心智。

但当前问题在于，前台封装程度较高，导致用户在关键下单节点无法获得足够的决策信息。平台强调统一保障，但用户又需要理解不同购买选项在渠道、成色、时效和售后上的差异。

本项目的目标不是拆穿供给来源，而是在不破坏平台统一正品心智的前提下，补足购买决策所需的信息透明度。

## 3. 核心问题定义

### 3.1 问题本质

当前得物 Buybox 的核心问题不是“购买选项太多”，也不是“标签文案单个难懂”，而是：

**平台统一正品心智与差异化购买决策之间存在信息表达断层。**

用户在购买选项页能看到价格、标签和物流时效，却难以理解这些差异背后的原因。结果是，用户会将“渠道、成色、履约时效、售后规则差异”误读为“正品保障差异”，从而产生不必要的正品焦虑和决策阻塞。

### 3.2 用户痛点

#### 痛点一：可见标签缺少下单场景内的官方解释

用户在购买选项页看到“品牌官方、品牌专供、全球购、保税直发、95 分”等标签，但页面内缺少触手可及的官方解释。用户不知道这些标签分别代表什么，也不知道这些标签之间的差异是否会影响正品保障。

#### 痛点二：时效差异容易被误读为查验差异

得物部分购买选项可以实现 1-3 天到货。由于得物核心心智是“先鉴别后发货”，用户容易产生疑问：这么快是否还有时间鉴别？

当前页面没有在购买选项决策节点解释“快速到货也经过查验或品质保障”的原因，导致用户容易被社媒谣言影响，形成“快到 = 没鉴定”的错误理解。

#### 痛点三：价格、时效、渠道和成色信息分散，用户缺少横向对比

当前购买选项列表更适合快速扫价格和时效，但不适合系统比较多个选项之间的差异。用户如果想知道“哪个最快、哪个更便宜、哪个售后更灵活、哪个是官方渠道、哪个是二手性价比”，需要在多个选项之间反复切换和记忆。

#### 痛点四：售后权益差异披露靠后，容易造成预期偏差

购买选项页上方可能展示平台统一保障信息，但不同购买选项因渠道、跨境链路或商品成色不同，实际售后规则可能存在差异。若用户直到确认订单页或更深层页面才发现规则差异，就容易产生“下单前没有说清楚”的感受，引发客服咨询、退货纠纷或负面评价。

#### 痛点五：社媒不实解读填补了官方信息空白

当官方信息在下单链路内缺位时，用户会转向小红书、抖音、知乎等平台搜索标签含义。但社媒内容中存在大量混淆渠道、成色、履约和查验关系的解读，例如“品牌专供是不是假货”“全球购是不是不查验”“次日达是不是没鉴定”等。这些内容会削弱得物平台正品保障心智。

## 4. 项目目标

### 4.1 用户目标

帮助用户在购买选项页快速回答以下问题：

1. 当前这些购买选项是否都经过得物查验或平台品质保障？
2. 为什么有些选项 1-3 天到，有些选项要更久？
3. 当前选项里的标签分别是什么意思？
4. 不同购买选项在价格、时效、成色、渠道和售后上有什么差异？
5. 如果我更在意速度、价格、售后、品牌渠道或性价比，应该怎么选？

### 4.2 平台目标

在不暴露具体供应商身份、不改变现有交易规则的前提下：

- 强化“不同购买选项均经过平台查验或品质保障”的共同信任底座；
- 降低用户因标签和时效误解产生的正品焦虑；
- 降低因售后规则理解偏差产生的客服咨询和退货纠纷；
- 缩短用户在购买选项页的决策时长；
- 提升购买选项页到确认订单页的转化效率。

### 4.3 方案边界

本项目不做以下内容：

- 不改变商品详情页底部购买栏，仍保持“立即购买”作为主入口；
- 不改变确认订单页主流程；
- 不改造得物实际查验、履约和售后规则；
- 不调整 Buybox 排序策略和流量分配逻辑；
- 不暴露具体供应商、卖家名称或后台供给身份；
- 不在购买选项卡片上大量新增标签；
- 不将普通渠道、不支持七天无理由等负面信息做成醒目前台标签。

## 5. 最终方案信息架构

### 5.1 页面范围

本期方案只涉及两个页面层级：

1. **尺码 + 购买选项页**
   - 保持原页面主结构；
   - 保持现有购买选项标签体系；
   - 新增一个「选项怎么选」入口；
   - 新增一句轻量信任说明，但不再额外放“查看”按钮，避免入口重复。

2. **选项怎么选页**
   - 页面标题统一为「选项怎么选」；
   - 页面内只保留三类模块：平台品质保障、当前选项对比、帮我选；
   - 标签说明、查验说明、售后权益说明不再作为独立长模块出现，而是沉入每个选项卡片的可点击 chip 中；
   - 页面底部提供「查看全部购买选项说明」入口，用于进入全量分类说明页。

### 5.2 核心交互原则

最终方案采用“轻页面 + chip 就地解释”的结构：

- 用户先看到当前选项对比；
- 每个购买选项卡片展示真实前台标签、价格、时效、权益 chip 和适合人群；
- 用户点击任一 chip，在当前卡片内就地展开说明；
- 用户需要系统了解全部标签和规则时，再进入「购买选项说明」分类页；
- 帮我选作为同一页面中的决策辅助模块，而不是单独的新页面。

这样既能保持下单链路简洁，又能在用户需要时提供足够解释。

## 6. 用户链路

### 6.1 当前链路

```text
商品详情页 → 点击立即购买 → 选择尺码 → 查看购买选项 → 选择购买选项 → 确认订单 → 支付
```

### 6.2 优化后链路

```text
商品详情页 → 点击立即购买 → 选择尺码 → 查看购买选项
                 ↘ 点击「选项怎么选」
                   查看平台品质保障 / 当前选项对比 / 帮我选
                   点击 chip 查看当前选项解释
                   点击「查看全部购买选项说明」查看分类说明
                 ↗ 返回或直接选择购买选项
              → 确认订单 → 支付
```

新增能力不打断高意向用户的原下单路径，而是为犹豫、焦虑、需要比较的用户提供辅助。

## 7. 功能方案

### 7.1 功能一：购买选项页入口

#### 7.1.1 需求描述

在“尺码 + 购买选项页”的购买选项区域新增「选项怎么选」入口。该入口是进入辅助决策页的唯一显性跳转入口。

#### 7.1.2 展示位置

入口建议放在购买选项标题右侧：

```text
购买选项                         选项怎么选 >
```

下方可增加一句轻量说明：

```text
当前可选方案均经得物查验，具体差异可在「选项怎么选」中查看
```

注意：该说明条只做解释，不再额外放“查看”按钮，避免与「选项怎么选」入口重复。

#### 7.1.3 列表标签规则

购买选项列表不新增复杂标签，仅保留用户当前已能看到的信息：

- 渠道标签：品牌官方、品牌专供、全球购、保税直发；
- 95 分标签：使用 95 分 logo + 成色描述，如“95 仅鞋盒瑕疵”；
- 普通渠道：继续不强行标注“普通渠道”；
- 不展示后台发货模式；
- 不在购买选项卡片上展示“不支持七天无理由”等负面售后标签。

95 分标签需要避免遮挡价格，展示时应控制宽度，过长成色描述可省略或截断。

### 7.2 功能二：「选项怎么选」页

#### 7.2.1 页面定位

「选项怎么选」页是购买选项页的辅助决策页，用于回答：

1. 当前选项是否都可信？
2. 当前选项差在哪里？
3. 我应该选哪个？

页面不做成“说明中心”，而是围绕当前商品、当前尺码、当前可购买选项进行即时决策辅助。

#### 7.2.2 页面模块

页面只包含三个模块：

1. 平台品质保障
2. 当前选项对比
3. 帮我选

不再单独展示“标签说明”“查验与时效说明”“售后权益说明”等长模块。

### 7.3 功能三：平台品质保障模块

#### 7.3.1 需求描述

页面顶部展示平台品质保障说明，先稳定用户对正品和查验的核心心智。

#### 7.3.2 建议文案

```text
当前可选方案均经得物查验或平台品质保障。
差异主要在价格、渠道、成色、预计到货和售后规则。
```

#### 7.3.3 表达原则

该模块只给结论，不承载详细解释。详细解释通过当前选项对比卡片中的 chip 展开。

### 7.4 功能四：当前选项对比

#### 7.4.1 需求描述

基于用户当前选择的尺码，展示该尺码下所有可购买选项的差异。该模块是「选项怎么选」页的核心。

#### 7.4.2 选项卡片字段

每个选项卡片包含：

1. 选项标题
   - 有渠道标签时，标题使用真实前台标签，如品牌官方、品牌专供、全球购、保税直发；
   - 95 分商品标题使用 95 分 logo + 成色描述，如“95 仅鞋盒瑕疵”；
   - 普通无标签渠道不强行命名为“普通渠道”，可根据页面语境展示为“全新选项”或仅展示价格与时效。

2. 价格
   - 展示当前购买选项价格。

3. 预计到货
   - 使用当前页面已有时效表达，如约 2 天到、约 5-6 天到、约 1-3 天到。

4. 可点击 chip
   - 渠道/成色 chip：品牌官方、品牌专供、全球购、保税直发、95 仅鞋盒瑕疵等；
   - 查验 chip：得物查验、95 分查验；
   - 售后/权益 chip：正品险、退货包运费、极速退款、二手商品售后规则、跨境商品售后规则等。

5. chip 展开解释
   - 用户点击某个 chip 后，在当前卡片内展开对应说明；
   - 同一张卡片内建议一次只展开一个说明，避免信息过载。

6. 适合人群
   - 用一句话说明该选项适合什么类型的用户。

#### 7.4.3 chip 展开说明示例

点击“得物查验”：

```text
得物查验：该商品已提前入仓或进入得物查验仓配节点，完成查验后可更快发出。
```

点击“品牌专供”：

```text
品牌专供：来自品牌相关渠道，可能包含得物专属或限定款，仍由得物提供查验或品质保障。
```

点击“退货包运费”：

```text
退货包运费：该选项支持符合平台规则的退货运费保障，具体以订单页权益为准。
```

点击“95 仅鞋盒瑕疵”：

```text
95 仅鞋盒瑕疵：该选项为 95 分二手商品，当前瑕疵主要集中在鞋盒或包装，商品售后适用 95 分规则。
```

#### 7.4.4 查验链路表达原则

查验链路不直接展示后台发货模式名称，而是翻译成用户能理解的履约解释：

- 快到选项：通常已提前入仓或进入得物查验仓配节点，完成查验后可更快发出；
- 常规选项：需先送至得物查验，通过后再发出，因此等待时间略长；
- 全球购/保税直发：按跨境或保税链路完成平台查验或品质保障，运输、清关或保税仓发出方式会影响到货时间；
- 95 分选项：由 95 分平台完成成色与品质查验，按二手商品规则履约。

### 7.5 功能五：查看全部购买选项说明

#### 7.5.1 需求描述

在当前选项对比模块底部提供「查看全部购买选项说明」入口，满足想系统了解所有标签和权益规则的用户。

入口示例：

```text
查看全部购买选项说明
渠道 / 成色 / 查验时效 / 售后权益 >
```

#### 7.5.2 页面标题

全量说明页标题为：

```text
购买选项说明
```

不要叫“全部标签说明”，因为该页不仅解释渠道和成色标签，还解释查验时效和售后权益。

#### 7.5.3 页面分类

页面采用顶部分类 tab：

1. 渠道
   - 品牌官方
   - 品牌专供
   - 全球购
   - 保税直发

2. 成色
   - 95 分
   - 全新未使用
   - 轻微使用
   - 仅鞋盒瑕疵
   - 仅包装瑕疵

3. 查验时效
   - 得物查验
   - 95 分查验
   - 提前入仓/查验仓配节点
   - 先查验后发出
   - 跨境/保税链路

4. 售后权益
   - 正品险
   - 七天无理由
   - 退货包运费
   - 极速退款
   - 跨境商品售后规则
   - 95 分商品售后规则

#### 7.5.4 页面说明原则

页面顶部保留统一说明：

```text
不同标签说明的是渠道、成色、履约或售后差异。
这些差异不代表正品保障差异。
```

每个条目采用短解释，避免百科化长文。

### 7.6 功能六：帮我选

#### 7.6.1 功能定位

帮我选是「选项怎么选」页中的同页模块，不是独立页面。它解决的是：

**用户已经看到当前选项对比，但仍不知道如何按自身偏好取舍。**

#### 7.6.2 交互方式

第一期采用单选主偏好，不做多选筛选。

偏好选项包括：

- 最快收到
- 价格更低
- 售后更灵活
- 品牌渠道优先
- 成色性价比

用户点击某个偏好后，在同一模块下方展示推荐结果。原型中的推荐结果态是同一页面向下滑动后的状态，而不是跳转到新页面。

#### 7.6.3 推荐结果结构

推荐结果包含：

1. 推荐选项
2. 推荐理由
3. 需要取舍

示例：

```text
推荐选择 ¥471 / 约5-6天到的品牌专供选项

该方案售后权益更完整，适合更在意售后灵活性的需求。

取舍：不是当前最快到货；想更快收到可考虑 ¥476 / 约2天到的选项。
```

#### 7.6.4 无完全匹配时的处理

帮我选不返回“无结果”，而是推荐最接近选项，并解释取舍。例如用户选择“品牌渠道优先”，但当前尺码没有品牌官方/品牌专供选项时，帮我选可以说明当前无品牌渠道选项，并推荐最接近用户偏好的方案。

#### 7.6.5 风险控制

推荐只能基于当前页面结构化信息和官方规则生成，不得编造权益、查验规则或到货承诺。

推荐文案避免：

- 绝对正品；
- 一定到货；
- 完全无风险；
- 保证最低价。

建议使用：

- 经过得物查验或平台品质保障；
- 预计到货时间；
- 当前页面显示的权益；
- 根据你的偏好更匹配。

## 8. 功能优先级

### 8.1 P0 必须实现

1. 购买选项页新增「选项怎么选」唯一入口；
2. 购买选项页新增轻量信任说明，不额外设置“查看”按钮；
3. 保持购买选项列表现有标签体系，不新增复杂标签；
4. 「选项怎么选」页顶部平台品质保障模块；
5. 当前选项对比模块；
6. 选项卡片内可点击 chip；
7. chip 就地展开解释；
8. 「查看全部购买选项说明」入口；
9. 「购买选项说明」分类页。

P0 解决项目核心问题：正品焦虑、时效误解、售后预期偏差和横向对比困难。

### 8.2 P1 建议实现

1. 帮我选单偏好推荐；
2. 推荐取舍说明；
3. 适合人群说明；
4. 「选项怎么选」页内一键选择某个选项。

P1 用于提升复杂决策效率。

### 8.3 P2 后续迭代

1. 根据用户停留、反复切换、返回等行为适时提示“需要帮你对比吗”；
2. 根据用户历史偏好默认突出更相关的推荐理由；
3. 接入客服高频问题，动态更新标签和售后解释；
4. 对推荐结果做点击、采纳和转化分析，持续优化推荐策略。

## 9. 数据指标与验证方案

### 9.1 核心指标

1. 购买选项页到确认订单页转化率
   - 验证用户是否更容易完成购买选项选择。

2. 购买选项页平均决策时长
   - 验证用户是否更快完成比较和选择。

3. 「选项怎么选」入口点击率
   - 验证用户是否存在明确的信息辅助需求。

4. 「选项怎么选」页选择采纳率
   - 用户进入页面后，是否选择某个购买选项并继续下单。

5. 推荐采纳率
   - 用户点击 关注点后，是否选择推荐选项。

### 9.2 辅助指标

1. chip 点击率
   - 观察用户最常点击的解释类型，是渠道、查验、成色还是售后权益。

2. 「购买选项说明」页访问率
   - 验证用户是否需要系统了解全部标签和规则。

3. 标签相关客服咨询量
   - 如品牌专供、全球购、保税直发、95 分等相关问题是否下降。

4. 查验相关客服咨询量
   - 如“次日达是否鉴别”“快到是否查验”等问题是否下降。

5. 售后规则相关客服咨询量
   - 如七天无理由、跨境售后、95 分售后等问题是否下降。

6. 因售后预期不一致导致的退货或投诉占比
   - 作为长期观察指标，不在 PRD 中伪造具体历史数据。

### 9.3 实验方式

可采用 A/B 测试：

- 对照组：原购买选项页；
- 实验组：新增轻量说明、「选项怎么选」入口和 chip 解释式对比页；
- 观察周期：至少覆盖不同类目、不同价格带、不同渠道组合商品；
- 分层观察：全球购/保税直发商品、95 分商品、多选项数量较多商品、快速到货商品。

## 10. 风险与应对

### 10.1 信息过载风险

风险：购买选项页空间有限，过多说明会干扰快速下单。

应对：购买选项页只保留一个入口和一句轻量说明，复杂解释进入「选项怎么选」页；在「选项怎么选」页中也通过 chip 按需展开，而不是默认展开长文。

### 10.2 负面信息影响转化风险

风险：直接展示“不支持七天无理由”等负面标签，可能放大用户顾虑。

应对：主展示采用“支持权益”和“适用规则”表达，必要边界在 chip 说明或「购买选项说明」页中中性呈现。

### 10.3 平台供给封装被破坏风险

风险：直接解释后台发货模式，可能让用户过度关注供应商身份。

应对：不展示后台履约模式名称，只解释用户关心的查验、时效和售后问题。例如使用“提前入仓或进入得物查验仓配节点”“先送至得物查验后发出”等用户可理解口径。

### 10.4 推荐可信度风险

风险：推荐若与页面规则不一致，或给出绝对承诺，会造成新的信任问题。

应对：推荐只基于结构化规则和当前页面真实选项生成；所有表达避免绝对化承诺。

### 10.5 规则维护成本风险

风险：不同渠道、成色和售后规则更新后，说明内容需要同步维护。

应对：标签说明、查验解释、售后权益和推荐统一依赖结构化规则表，避免散落在多个页面硬编码。

## 11. 原型设计说明

最终原型围绕四个状态展开：

1. **购买选项页入口态**
   - 保持原页面主结构；
   - 保持真实前台标签；
   - 新增「选项怎么选」唯一入口；
   - 轻量说明只作为解释，不再额外提供“查看”按钮。

2. **选项怎么选页 chip 展开态**
   - 顶部为平台品质保障模块；
   - 中部为当前选项对比；
   - 点击 chip 后在卡片内就地展开解释；
   - 页面底部提供「查看全部购买选项说明」入口；
   - 帮我选作为同页下方模块。

3. **推荐结果态**
   - 与第二张是同一页面；
   - 展示用户下滑后选择“售后更灵活”的状态；
   - 顶部仍是平台品质保障模块；
   - 当前选项对比仍保留相同结构，只是在滚动视口中露出部分内容；
   - 推荐结果在同页展示，不跳转新页面。

4. **购买选项说明页**
   - 作为全量说明页；
   - 分类为渠道、成色、查验时效、售后权益；
   - 解释所有可能出现的标签、查验链路和权益规则。

原型目标不是重做得物 UI，而是在尽量贴近得物现有购买链路的基础上，验证新增信息层是否能更好地支持用户决策。
